# Test run — 0.8.4

Everything in this folder was produced by running the tooling on the machine
described in [`05-environment.txt`](05-environment.txt), against the code as it
ships in 0.8.4. It is the evidence trail for the claims in
[`CHANGELOG.md`](../../CHANGELOG.md), not documentation — if you change either
script, regenerate it rather than editing the text.

The environment matters for this release in particular: the shell had **no
`PYTHONIOENCODING` and no `PYTHONUTF8` set, with a `cp1252` locale**. That is
the default Windows condition under which the 0.8.2 report crashed partway
through, so a passing run here is only meaningful because nothing was tuned to
make it pass.

## Reproducing it

```
pip install -r skills/kb-compiler/scripts/requirements.txt
python3 skills/kb-compiler/tests/run_tests.py
python3 test-runs/0.8.4/probes/verify_fixes.py
```

Both must exit `0`. `verify_fixes.py` takes an optional path to a
`skills/kb-compiler` folder, so it can be pointed at an older checkout to watch
the scenarios fail — which is how the before/after values in each docstring
were established.

## Why two test files

`tests/run_tests.py` is the permanent suite: it guards every detection against
future regressions and is the one to run after any change. `verify_fixes.py` is
tied to this release: it exists so the changelog's specific claims ("counted as
three findings", "lost one folder's documents") can be re-checked by running
something, instead of being believed.

## What is NOT covered

Honest limits of this run:

- **One platform, one Python.** Windows 11 with CPython 3.13.14. The scripts
  use nothing newer than 3.7 features, but no other version or OS was exercised
  here. The encoding and `isatty` defects this release fixes were both
  platform-specific, which is the reason to say so plainly.
- **Synthetic documents only.** Every `.docx` in these runs is generated by
  `python-docx`. Files produced by Word itself carry style and theme structures
  a generated document does not, which is exactly why the formatting checks are
  conservative and report anything they cannot resolve as "could not be
  verified" instead of a violation.
- **No real base.** Nothing here was run against a production knowledge base.
- **`os.path.getctime`** is still used for the "Creation Date" column, and means
  creation time on Windows but inode change time on Unix. Known, not fixed, not
  covered.
