What it does

Three things, and it does them the same way every time.

It knows the standard

Section order, Word formatting, the KB-XXX numbering, how the index spreadsheet is kept. You don't memorise any of it, and neither does the next person who joins.

It writes the documents

Ask in plain words and it produces the Word file, correctly formatted, with the index row ready for you to approve. It'll also convert a PDF, a slide deck, an email or a rough draft into one.

It checks the whole base

One command reads every document and cross-checks it against the index. Sixteen kinds of problem, counted, in a report that ends by telling you it changed nothing.

How it solves it

The problem isn't writing docs. It's that they drift.

Nobody sits down and breaks a knowledge base. It happens one reasonable edit at a time — and the damage is invisible until someone relies on it. So the fix has to be something you can re-run, not a one-off tidy-up.

Once, at the start

It asks where things live

Your folder, the label for document footers, and which language your documents are written in. It remembers, and never asks again.

Any time

You run the check

Seconds, read-only, on the whole base. Exit code 0 clean, 1 problems found, 2 couldn't run — so it works as a gate, not just a report you read.

Then

You decide, it does the work

It never edits on its own. It shows what's wrong and what it recommends; renaming, versioning and index updates happen once you say so.

What's left are the judgement calls it deliberately refuses to make for you: one document with no content to standardise, two histories missing their first entry, and a few files the owner chose to leave alone.

It would rather say nothing than cry wolf. Where Word leaves a formatting property unstated, the report lists it as “could not be verified” instead of calling it a problem. A report full of false alarms is one nobody runs twice — so that's the tradeoff it makes, on purpose.
